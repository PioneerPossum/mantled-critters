Idea raised 2026-10-03 (not built, no hardware bought as far as known): a Raspberry Pi based "TD/AV mixing unit" in the 10" rack that ingests stream data over dual 2.5G links (or eventually a UniFi XGS AP with a high-gain antenna), shows the mix on the rack display / HDMI out / a served web page with overlay, and records or sends to repositorium for "core memory recall/lessons".

Feasibility points I gave (verify before relying on them):
- "TD" assumed to mean TouchDesigner: it has no Linux/ARM build, so the Pi can only be an NDI endpoint/compositor fed by the Legion laptop, not the TD host. Unconfirmed what Gil meant.
- Pi 5: HW decode is HEVC only (no H.264 HW decode, no HW encoder), so multi-stream mixing is CPU-bound; NDI full-bandwidth 1080p60 is ~125-150 Mbps per stream, so two 2.5G links are far more than the Pi can decode. Dual 2.5G = PCIe NIC HAT (conflicts with a Hailo HAT unless a PCIe switch) or 2x USB3 RTL8156 adapters.
- Wireless path is limited by the Pi's client radio, not the AP; wired is the real path.
- Recording: repositorium has a 469GB NVMe, so recording raw NDI fills it in hours; record compressed (H.265) and write keyframe CLIP embeddings into the existing `events` table (VECTOR(512)) using melchior/balthazar's Hailo for recall.
- Related: [[esp32-av-ndi-streaming]] (ESP32 camera sources), [[magi-repositorium-ndi-wip]] (parked Dicaffeine NDI work on repositorium), [[magi-cluster-status]].

- CPU (4 cores) is the bottleneck, not the network or heat: throttled 0x0 throughout, peak 63.1C, 2.4 GHz held.
- NDI|HX proxy (ffmpeg on synthetic clips): H.264 software ~0.38 core per 1080p60 (~7 max); HEVC hardware (`-hwaccel drm`) caps at ~385 fps total = ~6x 1080p60 with almost no CPU. Unknown whether the NDI SDK's HX decoder uses the Pi's HEVC block.
- Gotcha: with several NDI sender processes on one host, mDNS advertised only the newest; connect receivers by ip:port. Resolume as one process should advertise all outputs.
- These are receive+decode only; compositing/HDMI output will use more, so plan on the comfortable numbers.
