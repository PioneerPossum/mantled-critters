**Rules (read before touching):**
1. A card is PRIVATE unless it carries an explicit `public` block {title, summary}. The validator refuses a public block containing IPs, MACs, ports, URLs, paths, credential words, tailnet names, the owner's name, places, health/medical, personal device names, "luks"/exposure talk. `magi-board scan` re-checks everything. A false positive just means reword or keep private.
2. Never put a secret value on the board, even privately; describe where it lives.
3. Update with the CLI, not by editing JSON: `magi-board card ID --title .. --column .. --summary .. [--public-title/--public-summary]`, `move`, `tick`, `log KIND "text" [--public ".."]`, `rm ID --into OTHER`, `import FRAGMENT.json`, `validate`, `scan`, `status`, `ack`. `magi-board --help` lists all.
4. Memory is point-in-time: cards say "as of <date>", not "is up".

**Auto-update (three layers, all in place 2026-10-09):**
- Project-scoped Stop hook (`~/Projects/claude-projects/.claude/settings.json`, runs `magi-board hook-stop`): if any MAGI memory note is newer than the board's `last_sync`, it blocks the stop ONCE and tells the session to update the board (or `magi-board ack`). Ignores `MEMORY.md`, `claude-code-*`, `feedback-*`, `secret-handoff*`, `session-execution*`, `lessons-learned`. Guard: `stop_hook_active` short-circuits so it cannot loop. It already worked on the very first day: parallel forks in this project added cards through it.
- `magi-board autosync` (timer): audire-monitor's `monitor.json` checks bad for 10+ min become `auto-*` Blocked cards; they close themselves (to Done, with a resolution log line) when the check recovers. No LLM involved.
- The private view shows a "board is behind" banner when memory notes are newer than the last sync.

- **Public-sync guard** (`sync_guard.py`, `magi-board guard [--history]`): `~/mantled-critters` is the PUBLIC repo and `sync-memory.sh` mirrors ONLY the memory directory into it, so board data is safe as long as it never enters the repo or the memory dir. `board.private.json` carries a random canary string; the guard greps the repo working tree and memory dir for it (any filename), checks for board file names, that the data dir and the backup dir are not inside a git work tree or the memory dir, and (nightly, `--history`) that the canary is in no commit. Tested by planting leaks. Memory notes themselves are already mirrored publicly by Gil's existing arrangement and scrub step ([[magi-github-sync]]); that is unchanged.
- **Nightly local backup** (`~/bin/magi-notes-backup`, `magi-notes-backup.timer` 03:40 daily, `Persistent=true`): hardlinked snapshots `~/backups/magi-notes/YYYYmmdd-HHMMSS/{memory,board-data}`, 14 kept, dir 700 / files 600. Order: guard first (refuses to write anything if it reports a problem, exit 3) -> rsync copy (board data copied under the board's own lock) -> checksum re-compare of source vs copy must be empty -> sanity (board copy has cards, index non-empty) -> `latest` symlink + `last-ok.json`. `magi-notes-backup --list` shows snapshots. First real run 2026-10-09 12:53: 114 cards, 45 notes, 3.1 MB; independently verified identical to live and a test restore parsed and passed the memory check. `magi-board autosync` opens a Blocked card `auto-notes-backup` if the service is failed or the last good backup is over 36 h old, and closes it on recovery.
