Recap built 2026-10-03 from a full read of every memory file. The format is: the trap (date), then the **Rule**, then the source. This file is append-only like the others ([[feedback-memory-incremental]]): add new lessons as dated sections at the end, and add a dated correction below an existing lesson if it turns out wrong. Do not rewrite or delete existing entries.

**Top rule:** memory is a point-in-time record, not live state. Verify before stating it as current.

## 1. Network / addressing

- **Reported hosts "down" using stale addresses from memory** (2026-10-02): I said the Netgear switch and edgerunner were down because they didn't answer on the 10.0.0.x addresses in old notes. The whole net had moved to 192.168.8.x on 2026-09-24 (switch .101, edgerunner .139), and a memory file already said so. **Rule:** before reporting live state (IP, up/down, service status) from memory, verify it: sweep the subnet, then confirm identity by hostname/MAC/SSH host key. If a memory says "superseded by [[x]]", read x first. Sources: [[magi-net-8x-migration-status]], [[feedback-memory-incremental]].
- **Hard-coded IPs break whenever addresses move** (2026-09-21 to 2026-10-02): tailscale serve targets, advertised /32 routes, the ssh alias, watchdog targets, `app.py` NODES and the redis bind all carried stale IPs after the move. **Rule:** when an address changes, grep every config and memory file for the old one. Prefer DHCP reservations, and record that an address is DHCP-assigned and can drift. Sources: [[magi-ups-power-down]], [[magi-net-8x-migration-status]], [[magi-router]].
- **Same-subnet secondary IP on a second interface broke the host's real address** (2026-09-14): a 192.168.8.51 alias on balthazar's wlan0 made its eth1 unreachable (weak-host ARP). **Rule:** don't alias a subnet onto a second NIC of a multi-homed host. Use a host that is only on the target segment. If you must do it, remove it right away and verify. Source: [[feedback-network-automation-caution]].
- **ARP flux on dual-homed Pis** (2026-09-24): the built-in NIC and the 2.5G dongle on the same /24 answered ARP for each other, so nmap paired the wrong MACs with IPs. **Rule:** use arp_ignore=1/arp_announce=2 (applied in `/etc/sysctl.d/99-magi-arp.conf`). Never use nmap MACs for identity on those hosts; use SSH host keys. Source: [[magi-net-8x-migration-status]].
- **Tailscale accept-routes swallowed LAN replies** (2026-09-21, 2026-09-24): edgerunner's table 52 / `ip rule 5270` sent replies to LAN hosts out tailscale0, so the LAN couldn't reach it. **Rule:** when a tailnet node is unreachable from the LAN but ARP works, check `ip rule` / table 52. The fix is `ip rule 5200 to 192.168.8.0/24 lookup main` (kept alive by ExitNodeAllowLANAccess=true). Sources: [[magi-ups-power-down]], [[magi-net-8x-migration-status]].
- **Exit node is not subnet access** (2026-09-22): routing through GL-E5800 as an exit node never gave access to the 10.0.0.x KVM. **Rule:** reaching a LAN IP needs an advertised and approved subnet/host route. An exit node only carries default traffic. Use narrow /32 host routes, not a colliding /24. Source: [[magi-wake-on-lan]].
- **tailscale serve answers only on the hostname** (2026-09-21): the bare tailnet IP returns 404. **Rule:** a 404 on the bare IP is normal. Test via `edgerunner.<tailnet>.ts.net:<port>`. Source: [[magi-ups-power-down]].
- **GL drop-in gateway mode with upstream DHCP still on** (2026-09-27): ~60 s periodic internet loss. The first hypothesis (kmwan health checks) was disproven by testing. The real cause was two DHCP servers / gateway takeover on one segment, fixed by putting the Xfinity gateway in bridge mode. **Rule:** read the vendor's documented prerequisites first, and test each hypothesis against a control path (a direct-to-modem rig) before acting on it. Source: [[magi-net-8x-migration-status]].
- **Taking the GL out of drop-in mode remotely "nuked the internet"** (2026-09-27, another session over the tailnet): the WAN PHY flapped and udhcpc never got a lease. **Rule:** router WAN-mode changes need Gil present, a fresh log bundle around the change window, at least 15-20 min after any modem-side change, and a monitor on the GL's LAN. Don't panic-revert in the first 60 s. Source: [[magi-net-8x-migration-status]].
- **Ignored the D555's own multicast as a "red herring"** (2026-09-14, corrected 2026-09-20): the camera was on its factory 192.168.11.55/24 and speaks DDS, not GVCP. The 239.255.0.1:7400 packets were the camera. A note also claimed it was "USB-only, not a network device"; that was speculation. **Rule:** don't dismiss unexplained traffic from an unknown subnet, read the vendor's setup guide early, and label speculation as speculation. Sources: [[d555-poe-setup-guide]], [[magi-cluster-status]].
- **NAT bridge for DDS** (2026-09-19): unicast MASQUERADE doesn't carry multicast (smcroute fixed that), and DDS's unicast handshake isn't NAT-aware, so pyrealsense2 still found 0 devices. **Rule:** for DDS/RTPS devices, use L2 adjacency or a known initial-peers config, not NAT. Source: [[d555-network-reconfig-status]].
- **Recorded "bridge is still live" but nothing persisted** (2026-09-19, corrected 2026-09-21): the secondary IP, MASQUERADE rule and route all vanished on reboot, and the wlan0 next hop had drifted (.140 to .141). **Rule:** make network changes persistent (NM profile, nftables, reserved next hop) and re-verify after a reboot before writing that they are "in place". Source: [[d555-network-reconfig-status]].
- **OSRM bound to the LAN IP, so localhost was refused** (2026-09-17, cost ~1 h). **Rule:** check the actual bind address (`ss -ltnp`) before debugging app code. Callers on the same box must use 192.168.8.184:5000. Source: [[magi-osrm-routing]].

## 2. Host identity

- **Fixed the wrong machine** (2026-09-14): I mistook edgerunner's wlan0 (10.0.0.138) for balthazar's Wi-Fi. **Rule:** run `hostname` over SSH before any config change when addresses differ only in the last octet. Source: [[feedback-network-automation-caution]].
- **Dongles swapped in the rack move, so identities rotated** (2026-09-24): IPs follow the USB dongle MAC, so .133/.175/.184 rotated among the three Pis twice. **Rule:** identify hosts by SSH host key fingerprint (`ssh-keyscan` vs `ssh-keygen -F`), never by IP. Never edit or clear known_hosts on HOST KEY CHANGED; check dongle placement first. Physically label dongles. Source: [[magi-net-8x-migration-status]].
- **Names that don't match** (ongoing): balthazar's OS hostname is still `dinky-pai`, and the `balthazar` ssh alias isn't in DNS, so `curl balthazar:8802` fails. **Rule:** use IPs for HTTP and expect `dinky-pai` in DHCP/hostname output. Sources: [[magi-backups]], [[magi-local-llm-feasibility]].
- **Same name, different thing** (2026-09-15/17): "oculus" is both the Dexcom Pi at Gil's partner's house and repositorium's old NDI role, D555 is not the D435i, and repositorium IS Caspar. **Rule:** don't merge devices or projects by name; confirm with Gil. Sources: [[dexcom-epaper-project-ref]], [[magi-repositorium-ndi-wip]], [[realsense-caspar-sensor-fusion]].
- **Session names lie** (2026-09-29): "macbook-runner-v1" runs on the Windows desktop. **Rule:** identify worker machines by what they report about themselves, not by session name. Source: [[magi-remote-worker-plan]].
- **Wrong guesses about edgerunner** (2026-09-21): "fresh NVMe = migration done" was wrong; root was on NVMe all along and it is still 32-bit armhf. **Rule:** check `uname -m`, `dpkg --print-architecture` and mount dates before assuming a migration happened. Source: [[audire-videre-monitor]].

## 3. Services and boot ordering

- **Redis bound to a LAN IP started before the IP existed** (2026-09-20). The network-online fix was then defeated on 2026-09-24 because the built-in NIC satisfied network-online while the dongle carrying .184 was absent (about 18k crash loops). **Rule:** a service that binds a specific IP needs a wait-for-that-IP ExecStartPre (now `wait-for-bind-ip.conf`), not just network-online.target. Check other IP-bound services the same way. Sources: [[magi-ups-power-down]], [[magi-net-8x-migration-status]].
- **Stopped is not disabled** (2026-09-20): the D555 streamer was only stopped, so it crash-looped thousands of times after a reboot. **Rule:** to keep a unit off across reboots, `disable` it too. Source: [[magi-ups-power-down]].
- **"Disabled" can be by design** (2026-09-24 and 2026-10-02): melchior's `magi-llm-api` is failover-only by design (role flip 2026-09-16). On 2026-10-02 it was treated as "installed but never started" and enabled at boot; whether that should stay is unconfirmed. **Rule:** before enabling or "fixing" a disabled unit, check [[magi-failover]] and the latest status notes for intent, and ask Gil if it changes a recorded design. Sources: [[magi-failover]], [[magi-net-8x-migration-status]], [[magi-router]].
- **Watchdog self-heal fought intentional stops** (2026-09-16): melchior restarted its own-duty roles on any stop, which masked the failover test. **Rule:** leave crash recovery to systemd `Restart=on-failure`. Watchdogs must not undo deliberate stops. Source: [[magi-failover]].
- **Coupled-service check missed own-duty roles after the role flip** (2026-09-16): hailo-ollama got restarted next to a running magi-llm-api, so two holders were on the chip. **Rule:** when role ownership changes, re-audit every "is the chip free" check, and update the hand-maintained `FAILOVER_NORMAL_DUTY` mirror in repositorium's `data_api.py`. Source: [[magi-failover]].
- **systemd wrappers** (2026-09-15): `bash -c` ExecStart must `exec` python so systemd tracks the real PID, and `setup_env.sh` must be sourced in every new shell or unit. Source: [[magi-cluster-status]].
- **Killing by name silently does nothing** (2026-09-15): hailo_apps' `setproctitle()` renames processes to "Hailo Detection App", `pgrep -f` over SSH matches its own argv, and relative-path launches can't be told apart. **Rule:** find Hailo holders with `fuser /dev/hailo0`, launch by absolute path, and don't use `pgrep -f` remotely. Sources: [[magi-cluster-status]], [[magi-dashboard]].
- **Stale UDP socket eats the stream** (2026-09-15): `udpsrc` uses SO_REUSEADDR, so a leftover process keeps receiving and the new one gets zero packets with no error. **Rule:** `sudo ss -u -a -n -p | grep <port>` to see every owner. Source: [[magi-cluster-status]].
- **Proxies drop new fields** (2026-09-16): the dashboard proxy dropped `session_id`, so history looked broken. **Rule:** when a field is added to a node API, update the `app.py` proxy too; they are separate files. Source: [[magi-dashboard]].
- **linuxserver.io images bake env on first boot** (2026-09-19): empty Mongo creds got stuck in `system.properties`. **Rule:** a wrong first boot means wipe `/config` and recreate. Source: [[unifi-network-status]].
- **Ran a bash script with `sh`** (2026-09-26): dash gave "syntax error ( unexpected". **Rule:** tell Gil to run `bash script.sh`. Source: [[unifi-network-status]].
- **Initramfs ordering** (2026-09-20): `PREREQ="cryptroot"` in local-top creates a tsort loop, and a VG spanning two LUKS PVs never auto-activates. **Rule:** use `scripts/local-block/`, test ordering under `dash` with a sandbox CONFDIR, and never activate `home` partial from the initramfs. Source: [[audire-videre-boot-lvm]].
- **Misleading timestamps and logs** (2026-09-20/21): Pis have no RTC battery, so early-boot journal time is the last shutdown time. edgerunner's journal is volatile. **Rule:** don't chase the time offset; use `last -x shutdown reboot` to tell a crash from a clean reboot. Sources: [[magi-ups-power-down]], [[audire-videre-monitor]].

## 4. Hardware quirks

- **Wake-on-LAN test stranded a node** (2026-09-21): a halted Pi 5 with a USB NIC does not wake on a magic packet, so melchior needed a physical press. **Rule:** don't shut down a remote node to test a wake path that isn't proven, and never take down all nodes at once. Remote power needs switched power (smart plug, PoE cycling). Source: [[magi-wake-on-lan]].
- **Under-voltage under LLM + detection load** (2026-09-16 onward): `get_throttled` showed live 0x50005 transients. **Rule:** check `vcgencmd get_throttled` before and after heavy NPU work, space out heavy requests, and stop on live bits that don't clear. Gil's PSU upgrade is the real fix. Source: [[magi-local-llm-feasibility]].
- **D555 specifics** (2026-09-15): no 640x480 (use 1280x720/896x504/640x360/448x252/256x144), and a bad USB cable or port causes a 1 s enumerate/disconnect brownout. Source: [[magi-cluster-status]].
- **ARM64 / armhf gaps:** no PyPI `pyrealsense2` wheels for ARM64; the official OSRM image is amd64-only (use `kradenko/osrm-backend:arm64`); edgerunner's 32-bit userspace can't run arm64 containers. **Rule:** check the architecture before choosing an image or wheel. Sources: [[realsense-caspar-sensor-fusion]], [[magi-osrm-routing]], [[unifi-network-status]].
- **Netgear GS308EPP UI** (2026-09-14): every write needs a fresh CSRF `hash`, the session limit locks you out for ~10 min, and unknown static paths return a 200 stub. **Rule:** one `httpx.Client` per script, log out, back off for real wall-clock time. An HTTP 200 doesn't prove a file exists. Sources: [[gs308epp-switch-api]], [[feedback-network-automation-caution]].
- **Geofabrik "latest" URLs redirect** (2026-09-17): plain `curl -O` saves the HTML redirect page. **Rule:** `curl -L`. Source: [[magi-osrm-routing]].

## 5. Hailo / GStreamer gotchas

- **apt wanted to replace the whole HailoRT family** (2026-09-15): the 5.4.0 gen-ai .deb pulled RPi `hailort` 4.23 and removed h10-hailort 5.1.1. hailo-ollama 5.4.0 also needs `libhailort.so.5.4.0` (SONAME) and the 3-argument `LLM::generate` API. **Rule:** always `apt install --dry-run` first, `apt-mark hold` the h10 packages, and check `readelf -d` for the SONAME before installing. Don't fake SONAMEs with symlinks. Source: [[magi-local-llm-feasibility]].
- **hailo-ollama can't share the chip with hailo_apps** (2026-09-16): concurrent use SIGSEGV'd hailo-ollama, or failed with HAILO_OUT_OF_PHYSICAL_DEVICES. Two hailo_apps processes using group "SHARED" can coexist (re-confirmed 2026-10-02 for magi-llm-api + magi-live-detect on melchior). **Rule:** stop hailo-ollama before starting any hailo_apps tool on that chip. Sources: [[magi-failover]], [[magi-local-llm-feasibility]].
- **Checked a "chip is free" premise too loosely** (2026-09-16): there was no systemd unit, but a manual 14-hour `Hailo Detection App` held `/dev/hailo0`. **Rule:** check `lsof`/`fuser /dev/hailo0`, not just systemd. Source: [[magi-local-llm-feasibility]].
- **Headless GStreamer stall** (2026-09-15): `autovideosink` with no DISPLAY stalls the whole pipeline silently. **Rule:** use the `fakesink` monkeypatch when DISPLAY is unset (now in shared `magi_detect.py`). Gtk 3.0 namespace errors mean installing `gir1.2-gtk-3.0`. Source: [[magi-cluster-status]].
- **2048-token context overflow broke every tool** (2026-09-17/18): each registered tool's schema counts on every request; going over gives `Context exceeds capacity` and "<" replies. **Rule:** budget system-prompt tokens when adding a tool, and trim the duplicated text. Source: [[magi-osrm-routing]].
- **The second generation after a tool call produced garbage** (2026-09-16/17, three shapes). Retrying with the same seed reproduces the degenerate output exactly. **Rule:** return the tool's own result text (the post-tool generate call was removed in Session 13). For degenerate no-tool output, retry once with a different seed. Source: [[magi-local-llm-feasibility]].
- **The small model invents structured data and picks wrong tools** (2026-09-16 to 2026-10-02): it hallucinated cities, used weather for "capital of Illinois", invented a `reverse` tool, and answered 17*23 = 321 with no tool (2026-10-02). **Rule:** never let the 1.5B model supply facts it wasn't given. Use app-side guards (location must appear in the user's text, server-injected lat/lon), keep math on the tool path, and escalate off-topic tool use. Sources: [[magi-local-llm-feasibility]], [[magi-router]], [[magi-osrm-routing]].
- **Local edits to vendored hailo-apps files get lost** (2026-09-16/17): the weather tool fixes live in the upstream checkout. **Rule:** keep reference copies in the repo (`shared/weather_tool/`) and re-check after any hailo-apps pull or reinstall. Source: [[magi-local-llm-feasibility]].
- **Small API gotchas:** hailo-ollama `/api/pull` takes `"model"`, not `"name"`; one GenAI session per chip (429 busy); `setup_env.sh` doesn't persist between shells. Sources: [[magi-local-llm-feasibility]], [[magi-cluster-status]].

## 6. Permissions / sudo

- **audire-videre has no passwordless sudo** (standing). **Rule:** use user systemd units with linger, use polkit-allowed nmcli, and ask Gil to run root steps. Never use the `docker` group as a root bypass. Sources: [[magi-cluster-status]], [[audire-videre-boot-lvm]], [[audire-videre-monitor]].
- **Classifier denials are intentional guardrails** (many: "Remote Shell Writes", "Security Weaken", "Modify Shared Resources", "Interfere With Workloads", "Out-of-Place Publication", "Unauthorized Persistence"). **Rule:** don't route around a denial with a different method. Hand the exact command to Gil, or propose the narrowest one-off permission rule. Sources: [[feedback-scoped-permissions]], [[magi-local-llm-feasibility]], [[magi-github-sync]], [[magi-router]], [[magi-dashboard]].
- **Broad grants** (2026-09-14): Gil always picked narrow one-off rules. **Rule:** propose the narrowest rule for the agreed command, and let Gil widen it if he wants. Source: [[feedback-scoped-permissions]].
- **SSH trust** (2026-09-24): a scratch known_hosts pinned to swapped keys was denied as "Security Weaken". **Rule:** fix the physical cause (dongle placement) instead of changing SSH trust. Source: [[magi-net-8x-migration-status]].

## 7. Publishing / credentials

- **Public repo** (2026-09-16): mantled-critters is PUBLIC. **Rule:** never stage `.env` files, switch creds, private keys, Redis/Postgres passwords or Tailscale keys. Push to `origin` (repositorium) only; `github` pushes need Gil. Sources: [[magi-github-sync]], [[magi-local-llm-feasibility]].
- **Memory to public repo** (2026-09-16): every attempt to copy memory out toward the public repo was denied. **Rule:** Gil runs `sync-memory.sh` himself. Source: [[magi-github-sync]].
- **Secrets never travel through chat or logs:** router/worker tokens are copied by Gil, not sent via messages; backups never copy private keys or print creds; don't open `~/Documents/Passwords.txt`; no credential recovery or bypass on the Xfinity gateway. Sources: [[magi-remote-worker-plan]], [[magi-backups]], [[magi-net-8x-migration-status]].
- **Exposure:** the dashboard has no auth, so it stays LAN/tailnet only (never `tailscale funnel`). Live-nav positions are logged at debug only, never stored. Source: [[magi-dashboard]].

## 8. Process / communication

- **Memory is append-only** (2026-10-03): add dated UPDATE/CORRECTION sections and never condense. Source: [[feedback-memory-incremental]].
- **Unquoted heredocs run backticks** (2026-10-03, while writing these memory corrections): a `` `wol_send.py ... 10.0.0.137 10.0.0.255` `` inside `cat >> file <<EOF` was executed as a command. It stopped at the script's MAC check, so no packet was sent. **Rule:** always quote the heredoc delimiter (`<<'EOF'`) when the text contains backticks or `$`.
- **The session freezes while Gil is AFK** (2026-09-20/21). **Rule:** coverage comes from systemd services (audire-monitor). On wake, read `events.log` / `monitor.json` for the gap instead of assuming nothing happened. Sources: [[audire-videre-monitor]], [[session-execution-model]].
- **Subagent liveness** (2026-09-21): a stale `.output` mtime doesn't prove an agent is dead. **Rule:** look for live child processes or changing files before stopping one, and never Read a full `.output`. Source: [[audire-videre-monitor]].
- **Subagent browsers fill /tmp** (2026-09-21, a 436 MB LV). **Rule:** brief agents to use `--user-data-dir` under `~/.cache` and clean up. Headless chromium hangs on http URLs here, so test via file://. Sources: [[audire-videre-monitor]], [[magi-design-references]].
- **Peer-down alerts are usually Gil's hands-on work** (2026-09-20/21). **Rule:** verify (ping, ssh uptime, `last -x`) before escalating. Push only for things Gil would act on, and ask before investigating as a fault. Sources: [[audire-videre-monitor]], [[magi-ups-power-down]].
- **Concurrent sessions edit the same live files** (2026-09-17): mid-test restarts caused RemoteDisconnected. **Rule:** expect other sessions; diff before editing; deploy melchior first, then balthazar. Source: [[magi-local-llm-feasibility]].
- **"Works" means the data path, not a process existing.** **Rule:** confirm end-to-end (e.g. `persisted ... from <node>` in the magi-worker journal), not just `systemctl is-active`. Sources: [[magi-cluster-status]], [[magi-failover]].
- **Parked WIP isn't cruft:** don't remove repositorium's Dicaffeine dserver. Ask what an abbreviation means ("TD" = Technical Director, not TouchDesigner). Sources: [[magi-repositorium-ndi-wip]], [[magi-av-mixer-idea]].

- **Trap (2026-10-02):** I reported melchior's `magi-llm-api` as "disabled, not failed" and enabled it at boot on Gil's "yes", without first reading [[magi-failover]], which records it as deliberately disabled/failover-only since the 2026-09-16 role flip (balthazar owns `language`). ## 2026-10-03 UPDATE: stream-load testing can take the whole LAN down; instrument first
- **Trap (2026-10-03):** high-rate NDI (4K UYVY, hundreds of Mb/s) plus VBAN were enabled with no per-second network logging running; a short whole-LAN routing stall then left no evidence (the 30 s watchdog needs 2 misses, so sub-minute events are invisible). See [[magi-net-8x-migration-status]].
- **Rule:** before any heavy streaming test, confirm `net-blip-logger` is active, know each sender's physical port (switch vs router), and make sure audio/video streams are unicast to a specific host, never broadcast.

## 2026-10-04 UPDATE: host-side UDP loss, isolate with a control stream before blaming the network
- **Trap (2026-10-03/04):** VBAN from the Legion lost ~85% in ~0.9 s blackouts; suspects in turn were the LAN, VBAN broadcast, the USB NIC, a USB hub, a 3-URB TX queue, Hyper-V bindings, repositorium ARP flux, Arena's OSC loopback flood and the Vantage Network Boost toggle. The real cause was Lenovo's kernel network filter **FBNetFilter** (FBNetFlt.sys), which kept rate-capping UDP even with the UI toggle off. See [[magi-net-8x-migration-status]].
- **What worked:** a same-rate sequence-numbered control stream (`~/Projects/claude-projects/ndi-bench/vban/ctlrecv.py`) sent from a known-good host (clean) vs the suspect host (lossy); comparing sender socket counts vs NIC SentUnicastPackets (drop above the NIC = host software); changing destination (single-homed host) and NIC (Wi-Fi) to prove it host-wide; then listing non-Microsoft running kernel drivers to find the one network filter. Record a driver's original START_TYPE before disabling it.
- **Rule:** when one host's traffic is lossy, prove where the loss happens (sender socket vs NIC counters vs receiver) before changing hardware; "app toggle off" does not mean the vendor's filter driver is unloaded.

## 2026-10-04 UPDATE: lessons from the AV/NDI session
- **Verify the content, not just the connection, in capacity tests:** the 01:37 NDI run looked fine at 235 Mbit/s because outputs were off/dark; the same layout with busy content was 826 Mbit/s and saturated the Pi. Check per-stream bitrate and resolution before trusting a run. See [[magi-av-mixer-idea]].
- **Multi-homed senders advertise unpredictably:** Arena advertised NDI on the stale Wi-Fi IP after a reboot; connect by explicit ip:port and check which IP actually has the port open.
- **Python frame conversion can be the bottleneck, not the encoder:** BGRA + swscale was 18 ms/frame; receiving native UYVY and building planes with numpy was 2.5 ms. Also set PyAV encoder thread_type AUTO (default is far slower).
- **Long-running services should idle cheaply when their source is absent** (Gil's "dynamic sleep"): no crash-loops, no work when nothing is connected.
- **/boot on audire-videre is tight (~200 MB free, 215 MB initrds):** any package that rebuilds the initramfs (e.g. NVIDIA driver) needs space freed first (remove the old kernel).
- **Approvals relayed by a peer session are not the user's approval:** confirm installs/persistent changes with Gil directly in this session (he answered "approved"/"enable osc" here when asked).

## 2026-10-04 additions (post NVIDIA-driver reboot)
- **Bundled-FFmpeg wheels can outrun the distro GPU driver** (2026-10-04): installing the nvidia driver did not make NVENC usable from PyAV 18.1/15.1, whose bundled FFmpeg demands NVENC API 13.0 (driver >=570) while Kali ships 550.163 (API 12.2). The symptom is only `Function not implemented (38)`; the real reason is in the libav log. **Rule:** when a GPU encoder "does not implement", raise `av.logging` to VERBOSE (or run the ffmpeg CLI) to read the driver/API line before debugging the install; try the distro's own ffmpeg, which is built against matching headers. Source: [[magi-av-mixer-idea]].
- **The session scratchpad lives in /tmp, which is only ~436 MB here** (2026-10-04): a pip venv in the scratchpad hit "No space left on device". **Rule:** put venvs, downloads and test media under /home (e.g. `~/magi-video/...`), keep scratchpad files tiny, and delete test artifacts when done.

## 2026-10-05 (VJ control build)

## 2026-10-09: building the MAGI-CLUSTER BOARD ([[magi-board]])
- **A "static" status file was a data leak** (found 2026-10-09): `board.json` sat in the dashboard's static folder, which Flask serves raw, so addresses and tailnet names were readable by anyone on the LAN. **Rule:** private data never lives under a served static dir; publish the public view as a computed projection (allow-list of fields, fail closed), not as a file someone has to remember to sanitize.
