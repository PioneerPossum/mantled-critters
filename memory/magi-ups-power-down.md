- **Wi-Fi asymmetry root cause:** edgerunner accepts tailscale subnet routes (`RouteAll: true`, exit node set), so its routing table 52 has `192.168.8.0/24 dev tailscale0`, and `ip rule 5270 lookup 52` beats the local wlan0 route. Edgerunner-initiated traffic to the LAN works (hairpins via the tailnet). Consequences: the D555 bridge design that used `route 192.168.11.0/24 via <edgerunner wlan0 IP>` from audire-videre would NOT work now; reach edgerunner from the LAN via eth0 (10.0.0.137, through the router NAT) instead. I did NOT change it: RouteAll/exit node is probably Gil's deliberate remote-access path to the home LAN, and edgerunner is due for a reinstall. If it must change: `tailscale set --accept-routes=false` (would lose the tailnet route to 192.168.8.0/24 via the subnet router) or add `ip rule add to 192.168.8.0/24 lookup main pref 5200`.
